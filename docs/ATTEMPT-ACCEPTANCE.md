# Attempt archive acceptance

The frozen `attempt-archives` profile has nine named callbacks. The required
runtime controller runs them against source and a fresh offline production
installation. Public fixtures are original synthetic inputs; these controls do
not invoke a model or inspect evaluation cases.

The broken, repaired and valid alternate programs execute two actual consumers
of the same producer. Each consumer has an exact and adjacent identifier case.
The broken witness retains both failures and both successes with the actual
native process PID. Changing either consumer alone must change its observed
outcomes while the producer and other consumer remain unchanged. Repair changes
the source identity, preserves operator policy and case inputs, and creates new
attempt and journal identities.

Detailed receipts retain physical header and frame buffers, byte counts, hashes,
ordered calls, actual process identities, raw stdout/stderr and terminal states.
Replay reconciles those bytes rather than trusting an advertised result. The
storage control writes an actual oversized native report into bounded hashed
Tasks chunks, closes the database, reopens it and reconstructs the exact report
and journal. It does not promise durable results for every killed CLI process.

The prerequisite control refuses absent or changed adapter manifests, changed
pinned entry bytes and an unsupported runtime before the adapter writes its
execution marker. Source changes after native imports make the final report
incomplete even when every observed case passed. Empty and genuinely skipped
case bodies remain incomplete despite a complete process journal.

Library, CLI and stateless MCP controls preserve startup-only execution trust.
Tool arguments cannot enable execution, install a journal context or grant source
disclosure. Default summaries omit raw journals and source. Detailed execution
receipts and review source disclosure have separate operator permissions. A
synthetic ambient secret is withheld from native children and output. No provider request is made and no actual credential is recorded.

Cancellation, deadline and output exhaustion controls reach a real native output
frame after both consumers import and execute. Each run also reaches a native
descendant. Receipts preserve the observed prefix and interrupted or failed
accounting; the worker and descendant must be gone, the owned journal namespace
removed, and an unrelated sibling still alive. The fixture observer records
actual engine-created directory names without substituting filesystem or process
results. This is trusted execution with owned cleanup, not a sandbox.

The runtime receipt binds the immutable harness, frozen callback names, exact
non-skipped terminal events, compiled source/installed engine bytes, package,
external MCP client version, Node executable and observed runtime metadata.
Imported engine dependencies and actual module loads are not traced. Hosted
image metadata and Docker image IDs are observations, not host attestations or
verified producer source builds. Development receipts with no selected slot do
not qualify a frozen runtime slot.

The runtime controller also executes the original frame codec, private storage,
streamed invocation, wrapper catalog, engine journal, physical process output and
offline API-attempt callbacks as a separate foundation ledger. Their required
names and files are reconciled against the preserved source manifest. Every
selected callback must have exactly one non-skipped terminal event, bound to its
unchanged test file. Missing, duplicate, extra, skipped, truncated or inconsistent
file/event/case evidence fails acceptance even if the whole-profile count passes.
The same foundation runs through the unchanged external harness against the fresh
production install in that runtime cohort. Controls that copy the engine into
another fixture resolve its runtime dependencies through copies from that same
fresh locked installation. The external MCP test client has a separate dependency
root and cannot overwrite those production dependency copies. Windows explicitly excludes only the
POSIX ordinary-descendant ownership callback; native POSIX slots retain it.

A pinned Go 1.27.1 executable runs the physical archive broken/fixed control.
Version, target OS, architecture and executable digest are observed before/after
both cohorts and must match. Missing or different Go is unavailable acceptance;
the controller does not install or download it. Hosted jobs provision the exact
version before the archive controller; the native ARM image supplies its pinned
Go toolchain. The whole-feature nine-case ledger remains separate from these
foundation controls. The API controls use fully scripted transports for both
provider protocols, including failed and successful attempts; they contact no
provider. External Codex/Claude host usage remains unknown unless independently
supplied. The complete call-family and frozen runtime receipt reconciliation,
artifact/license closure, evaluation protocol freeze and Gate A remain pending.

The shared named-profile collector uses the same bounded fresh callback workers
and 600-second collection allowance for `attempt-archives` as the runtime
controller. Individual callback deadlines and production execution/cleanup limits
remain unchanged. Implementation and receipt collection are declared separately
from the still-pending selected runtime and artifact/license qualification.
