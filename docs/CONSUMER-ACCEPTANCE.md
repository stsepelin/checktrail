# Whole consumer-impact acceptance

The frozen consumer-impact callbacks exercise a shared JSON policy read by a
producer and two independent native consumers, plus an unrelated project. A
prefix defect fails both consumer assertions. The repaired and valid adjacent
cases pass, and an affected plan executes fewer projects than full validation
while retaining both failing consumers. Removing a declared consumer edge
requires full validation and retains the same native failures.

Planning reads source and configuration without running the fixture. Unsupported
language inputs retain the full plan. Separate native language context profiles
supply their own producer/consumer execution evidence; these callbacks do not
infer language execution from an import graph or broaden the finite Node import
resolver.

Missing history, a missing runtime, malformed project metadata, empty checks and
skipped consumers remain distinct from successful evidence. A source change made
after native readiness invalidates an otherwise successful aggregate. Library,
CLI and MCP checks compare summary plans and preserve operator-only execution
permission. Cancellation, deadline expiry and output exhaustion each reach a live
parent and child before verifying terminal cleanup.

`node scripts/verify-consumer-runtime.mjs SLOT` requires the exact frozen cases
from source and from a fresh offline production installation. The installed
harness stays outside the package, uses the pinned external MCP client, and
repeats the same callbacks. Receipts compare engine, package, harness, callback
inventory and observed runtime identities before and after execution. Skipped,
missing, duplicate, renamed, truncated and changed-byte evidence is rejected.

Selected runtime checks bind the exact Node version, platform, architecture and
OS/image family. The Linux ARM64 workload builds from pinned Node and Git-bearing OS images
without package-manager downloads. It records both base references, the build
definition digest and the separately observed Docker image ID. Git version and
executable bytes are observed before and after source and installed controls. Windows also records the fixed system
PowerShell digest. These observations do not attest a host or container and do
not trace loaded modules, dependency bytes or producer source builds. A call with
no slot is a development observation and cannot qualify a hosted runtime.

The same runtime cohort also requires the original Node import/resource,
Git-selection and paired-impact foundation controls from source and the fresh
production installation. Their ledger binds each unchanged file, each required
top-level callback and every original nested unknown-source control. Nested
terminal events remain separate from top-level requirements; an advertised total
cannot replace a missing, skipped, duplicated or foreign event. The whole-feature
ledger stays separate. The external harness captures the paired-impact scripts
and both original corpus versions, their retained historical development snapshots,
and the compiled fixture dependencies.

The existing Tasks runtime jobs invoke the controller without adding jobs.
Qualification remains pending until the selected matrix supplies current source
and installed receipts and the native language witnesses are reconciled. The
consumer implementation is declared, while selected runtime qualification and Gate A
remain pending; no review trial, model inference or
review-quality claim follows from these development controls.
