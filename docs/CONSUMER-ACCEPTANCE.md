# Whole consumer-impact acceptance

The `consumer-impact` profile exercises broken, repaired and valid near-miss
workspace changes, prerequisite refusal, source freshness, empty/skipped tests,
privacy and operator trust, cancellation and fresh installed-package behavior.
Its original synthetic workspace has separate producer, affected consumers and
an independent project. Broken selected and full runs must retain the same
consumer failures; a repaired selected run must execute fewer checks.

`scripts/verify-consumer-runtime.mjs` requires the complete selected profile
from source and a fresh offline production installation. The external installed
harness binds the selected source files, callback requirements, package and
production dependency lock, observed runtime and compiled engine bytes. It also
preserves the original import, Git-selection and paired-impact foundation cases,
including their nested terminal events. Missing, duplicated, skipped, stale or
foreign receipt entries fail admission.

The runtime controller supports the selected engine matrix. Its checks compare
observed metadata; they do not attest a host or qualify another runtime. CI wiring
adds the cohort to each selected Tasks runtime slot, with a separate pinned
Linux ARM64 controller. These new hosted runs remain unverified until observed.

[The development measurement](measurements/consumer-impact-development-2026-10-28.json)
records successful source and fresh-install execution on the observed current
Mac. No final runtime slot was selected, so this observation does not satisfy
the frozen runtime matrix. It does not close other language/framework consumer
chains, artifact/build/license closure, independent evaluation or Gate A.
No inference or field evaluation ran.
