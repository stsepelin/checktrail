# Native Roslyn generator evidence

The fresh `dotnet.build` and `dotnet.test` profiles accept explicitly declared
C#/Visual Basic outputs from a freshly built C# Roslyn generator project. This
profile uses SDK 10.0.401, runtime/reference pack 10.0.12 and `net10.0`. It is not
part of the published alpha.5 package. E12 remains partial and Gate A stays open.

## Declare native outputs

Use the [build/dependency contract](DOTNET-BUILD.md). Each consumer project can
add `roslynGeneratedSources`, separate from `generatedSources`: the latter names
MSBuild-produced compiler inputs, while Roslyn outputs are produced inside the
compiler. An omitted declaration defaults to an empty array. For example:

```json
{
  "roslynGeneratedSources": [
    {
      "file": "CSharp/obj/Debug/net10.0/generated/Original.Generator/Example.OriginalGenerator/GeneratedCounter.g.cs",
      "generatorProject": "Generator/Generator.csproj",
      "generatorClass": "Example.OriginalGenerator"
    }
  ]
}
```

The producer must be a declared C# library, distinct from the consumer, with
inventoried source and a package lock. The emitted path must use the consumer's
fresh conventional output directory, producer assembly name, exact generator
class and consumer language extension. The consumer project must actually select
the producer as a compiler analyzer. Declaration does not create that reference.
Discovery and planning inspect inputs without invoking either project.

## Reconcile participation

Operator trust is required before running MSBuild targets, native compilers or
generator code. The shared engine copies the complete inputs and pinned dependency
closure into a fresh workspace, enables emission to the declared conventional
output directory and rebuilds every project. Caller-owned outputs remain separate.

Every emitted C#/VB source in that directory must have an exact declaration.
Each declared output binds the fresh producer assembly and its observed digest,
the native compiler's actual analyzer input, native emission properties and task
parameter, generated bytes and both source digests. The producer's native metadata
must expose the exact directly implemented Roslyn generator interface and an
initializer with sequence points in its declared source. The consumer's portable
symbols must include the generated source with its matching checksum. Missing,
extra, duplicated, disabled or source-unbound participation cannot produce a pass.
The generated sources remain part of the complete compilation-source closure and
its pre/post checks. Ordinary warning diagnostics retain their native identity;
a generator warning without a source address does not invent one.

The test profile executes native consumer cases against those fresh generated
outputs and retains its discovery, source-method and TRX requirements. Successful
compilation alone does not prove that a consumer test ran.

## Required test plan

The `dotnet-generated` profile in
[required-native-tests.json](../scripts/required-native-tests.json) requires exact
original callback identities without skips. Its coverage target is every declared
project, emitted source and consumer test case, rather than a line-coverage score.

| Type                  | Critical behavior and controls                                                                                                                                                                                                                               |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Declaration           | Strict schema, malformed/foreign origins, invalid producer, duplicate output, wrong language/path and no planning execution.                                                                                                                                 |
| Native build/test     | Original C# generator emits both C# and VB; consumer boundary regression fails the actual NUnit case and repairs; producer errors retain their source address; qualified interface spelling and the classic direct generator contract are valid near misses. |
| Evidence contract     | Missing/extra outputs, generated hashes/sizes, producer artifact/analyzer selection, emission settings, direct generator interface, initializer source and consumer portable-symbol participation.                                                           |
| Failure and ownership | Missing emission, sibling output and generator exception stay incomplete; existing caller output survives; no caller build directory is created.                                                                                                             |
| CLI/MCP               | Generated consumer failure, summary privacy, negotiated protocol, startup/operator-only trust and repaired result.                                                                                                                                           |
| Lifecycle             | Reach the actual original generator inside the native compiler before cancellation; reap its descendant/compiler and remove owned native scratch and outputs.                                                                                                |

Run `node scripts/verify-dotnet-generated-container.mjs` with the original prepared
image/cache described in DOTNET-BUILD.md. Source acceptance and a fresh offline
production installation are separate required runs. The external harness imports
shipped runtime bytes and exercises the installed CLI; original fixtures and the
official MCP client remain outside the production package. Hosted CI is configured
but has no recorded result for this revision.

[The native receipt](measurements/dotnet-generated-native-2026-10-06.json) binds
source/installed acceptance, compiling guard mutations and preserved .NET profiles.
These original synthetic controls use no reviewer inference or real-project field
cases and do not measure review quality.

## Unverified scope

The bounded profile requires directly implemented `IIncrementalGenerator` or
`ISourceGenerator` contracts and a source-bound initializer. Inherited/generic
contracts, generators without sequence-bearing initialization, syntax-only outputs
absent from portable symbols, external generator packages, nested hint paths and
F# generator consumers need separate acceptance. Generated-source whitespace,
code-style and analyzer-fix formatting are unavailable; the formatter keeps the
whole declared generator plan unavailable instead of narrowing its scope.

Wider SDK/framework/target/platforms, custom test-name method provenance, full SDK
and publisher/license attestation, and hostile-project OS containment remain open.
Fresh directories and the prepared offline development container are not an OS
security sandbox.
