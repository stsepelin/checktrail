# Native consumer witness evidence

The selected consumer-family manifest keeps nineteen required family boundaries
visible. Families marked prepared have their original producer/consumer witness
and controller hooks integrated. Other families remain required and pending.
This is development acceptance tooling, not a review-quality result or complete
consumer-family qualification.

The optional test helper captures source bytes before and after the native
invocation, the observed compiler/interpreter and executable bytes, bounded
physical stdout/stderr, and the actual producer/consumer answers and source
observations returned by the original witness. Each actual returned process result
is atomically retained before success assertions, including failed, unavailable,
timed-out, cancelled and truncated results. These observations reuse the shared
bounded physical output contract; they do not invent a process-start PID or
interleaved stream order after the process has exited. Successful witness rows
reference the exact private attempt bytes, source, variant and stage. Missing,
altered, duplicate, reused, unmatched or failed attempts leave qualification
incomplete. Storage failure remains sticky and cannot be turned into success. Raw observations do not qualify
through a callback name or a runtime label. The normal tests do not enable this
capture unless the operator provides private storage.

`node scripts/verify-consumer-witness-profile.mjs PROFILE` runs the existing nine
required callbacks, including the fresh offline installation, for one of
`context-go`, `context-python`, `context-php`, `context-rust`, `context-ruby`, `context-c`, `context-cpp`, `context-java`, `context-kotlin` or `context-scala`. It requires an operator-prepared native environment and
executes original synthetic fixture code. These execution constraints are not an
OS security sandbox. CLI/MCP project discovery does not call this controller.

A controller binding reconciles the actual terminal test file and event ledger,
engine and observer/helper bytes, selected requirement identities, tool bytes and
runtime observations. The installed harness deliberately contains only its selected
requirements; unrelated profile declarations do not change the selected helper
identity. Package-manifest hashes identify `package.json`, not a package archive.
The existing offline installed acceptance remains separately required. Dependency,
whole-package archive, hardware and complete producer-build attribution are not
inferred from these witness packets.

Existing PHP, Rust, Ruby, C, C++, Java, Kotlin and Scala container controllers bind their observed image IDs and
native runtime probes. The Go/Python hosted-runtime controller records OS release
and runner-image metadata without claiming host attestation. Unselected development
hosts remain unqualified. Each selected variant must have one source and one
installed canonical observation; missing, duplicate, skipped, changed or foreign
bindings cannot complete a family. Every unobserved family keeps the aggregate
incomplete.

The current implementation has pure synthetic packet controls. Source/fresh native
collection and the complete required runtime acceptance remain pending. Gate A,
complete upstream build/license closure and independent evaluation remain open.
No model inference, comparison trial or field evaluation is invoked here.

The Go/Python entry point is the final hosted controller and refuses unqualified
family reports, even when all six native observations exist. PHP/Rust/Ruby/C/C++/JVM inner
collection stays unqualified until the outer controller binds the observed OCI
image identity and requires the complete family report. Completion of these
individual families does not complete the nineteen-family aggregate or Gate A.

Ruby reuses its original interpreter witness and source/fresh acceptance callbacks.
The physical response includes all three consumer calls, including the alias,
and original producer/caller byte arrays read by the Ruby process. No optional
JSON or digest gem is needed by this witness. Native Ruby qualification remains
pending until the selected OCI controller actually runs and binds its results.

C/C++ retain the original seven producer cases and both consumer outcomes. Their
compiler and executable invocations have separate retained attempts and byte
identities; a missing or failed compiler attempt cannot be replaced by a successful
executable result. The existing controller observes supplementary GCC/G++ 14.2.0,
its Debian identity and aarch64 target. These observations explicitly do not
qualify the selected Clang toolchain. Native source/fresh qualification is pending.

Java/Kotlin/Scala keep compiler and runtime attempts separate. The collector
observes the actual Java runtime, compiler launcher, JDK module image and every
JAR selected by the original compiler/runtime classpaths. Version or archive
labels cannot fill missing dependency observations. The complete generated class
directory is observed after compilation and after execution; the actual compiler
output argument and runtime classpath must bind that same directory. Missing
producer/caller classes, changed artifacts, changed dependencies and foreign
classpaths refuse qualification. These collectors are prepared; native JVM
source/fresh acceptance and the final selected matrix remain pending.

Classpath observation includes both `.jar` and `.JAR` names, ignores ordinary
non-recursive subdirectories, and refuses a directory whose name itself matches
the wildcard. Such an unsupported directory cannot disappear from qualification.

Every compiler/runtime classpath entry is derived from the actual command vector
and must match the observed output directory and selected JAR directory or
runtime JAR. An additional or redirected dependency cannot be qualified by an
unrelated library observation.

The shared managed adapter prepares C#/F#/VB observations without marking their
fixture hooks prepared before integration. It observes the actual dotnet host,
compiler directory/deps/configuration, complete selected reference DLL set, CLR
runtime and hostfxr payloads. Runtime and hostfxr version-directory inventories
must each contain the frozen version alone; additional versions cannot hide
roll-forward selection. The pre-compiler seed contains the exact runtimeconfig
and, for F#, its byte-matching copied FSharp.Core. Witness.dll must be produced
after that seed and stay unchanged through the actual consumer invocation.

C#/F#/VB now have their original fixture and OCI controller hooks integrated.
Their compiler/runtime acceptance remains pending; a prepared hook, SDK label or
synthetic control is not a selected native result.

## Current-source native matrix transport

`node scripts/verify-consumer-native-acceptance.mjs --list` enumerates the frozen
operator acceptance scopes without executing their controllers. A selected
`PROFILE RUNTIME_SLOT` invocation awaits the existing fixed controller with its
original arguments and native execution limits. This is internal development/CI
tooling; an MCP argument cannot enable it or grant execution trust.

The invocation captures actual controller writes privately and reconciles the
original required callback ledger, current engine/harness/source identities,
selected tool bindings and all retained native attempts. Docker collection uses
an owned private volume initialized for the image's observed user, including
nonroot users. Fixed read-only extraction verifies native identities against the
registered namespaces before copying bytes. Host collection reads only explicitly
registered namespaces with verified private ownership/ACLs. Windows keeps its
custom capture-parent refusal and uses the existing protected default namespace
contract. Failed or incomplete originals remain private diagnostics.

Only a successful reconciled scope publishes a sanitized capsule to the
operator-selected output directory. Raw packets, stdout/stderr, namespace paths
and attempt files remain private and are never uploaded by the workflow. The
capsule records controller module completion without claiming that the same
process observed its own exit or a native process-start acknowledgement.

The CI completion step independently requires successful outer jobs and exact
current-run/attempt artifact names. It rejects missing or duplicate scopes,
foreign source/engine/lockfile identities, omitted source/fresh scenarios and
reused witness, process-attempt or registry identities. Artifacts remain separate
rather than overwriting one another during download. Related-scope CI may qualify
only its selected subset; consumer profile completion requires every declared
family/runtime scope and the separate selected-Clang obligation. Hosted Windows
also requires its actual Windows-only ACL and host-custody inventory; optional
skips on another operating system do not satisfy it.

These controls and transport wiring do not themselves qualify the current native
matrix. The manifest's native acceptance remains pending until actual exact-source
source/fresh execution and complete aggregation. Whole upstream build/license
closure, host/client isolation and independent evaluation remain separate Gate A
requirements. No model or field trial runs through these entrypoints.
