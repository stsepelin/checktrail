# Selected operator provenance composition

The internal `scripts/native-provenance-coordinator.mjs` prepares an
operator-pinned external adapter bundle for the existing shared engine. It
composes the production and development npm audits, the retained four-family
artifact evidence audit, and explicit operator proof selections for Random,
Scala, Fantomas and the captured-source runtime. It adds no public MCP tool or
legal-policy API.

The operator supplies dedicated canonical audit input roots and a private journal
outside those roots. Preparation captures their complete bounded physical file
identities and the selected engine, coordinator, Node and npm CLI identities.
The staged npm auditor must exactly match the bundled first-party program; its
module location binds the audited npm root. Both input roots are checked again
after observation. Planning and discovery inspect the pinned bundle without
executing the coordinator or importing project modules. Execution still requires
`--trust-project` or MCP startup `--allow-execution`; tool arguments grant neither
execution nor proof authority.

The optional audit argument `--npm-cli ABSOLUTE_FILE` selects a canonical,
bounded operator npm CLI. It executes through the selected Node with the closed
`ls` arguments, without a command shell or current-directory shim. The auditor
checks that CLI entry file before and after inspection. This entry-file identity
is not complete npm/compiler/bootstrap provenance. Existing standalone auditor
invocations retain their previous default selection.

Consistent observations and a scoped signature or attestation are separate from
complete producer, original-notice and legal applicability closure. Valid npm
gap reports, including exit 2, remain incomplete. Malformed evidence, changed
inputs or execution failures remain explicit errors/incomplete observations.
Every planned audit and proof slot retains an observed or unrun disposition.
The coordinator never marks complete original notice coverage, compiler/SDK
closure, legal compliance or Gate A as verified. It does not perform native
cryptography or reproduce a producer build itself. The existing family readers
retain their exact independent scopes; unselected proof slots are explicit.

Requested project files remain explicitly unavailable: an invocation fingerprint
does not show that the external operator audit inspected those project files.
The coordinator rechecks the selected Node/npm entry files after observation.
Truncated or over-budget raw output remains incomplete, with its loss flag
retained. The external runner retains the bounded coordinator witness in detailed
process output; normal library/CLI/MCP summary projections omit that witness, root paths
and proof material. The private journal records attempts and terminal accounting.
POSIX owner/mode checks and the existing Windows ACL inspector govern its storage;
a missing ACL observation cannot become private-storage acceptance.

The nine exact `native-license-provenance` callbacks live in
`test/gate-native-license-provenance.test.ts`. Select them explicitly with
`CHECKTRAIL_NATIVE_LICENSE_COMPOSITION_NATIVE=1`; unselected callbacks are skipped,
not passing qualification. Their fixtures contain fictional package/component
material. The lifecycle-only inspection command emits no metadata and proves only
that cancellation/deadline reaches and cleans an owned child. The installed case
uses coordinator and engine modules from a fresh offline production install,
with the operator bundle outside it. No review or field trial is involved.

The existing `tasks-runtime` workflow's seven `matrix.core` rows select the
source/fresh controller after the build and production-cache preparation, with a
ten-minute step ceiling. The separate Windows consumer row does not repeat that
selection. The eighth profile, `native-linux-arm64-node22`, runs through the
existing `tasks-runtime-arm64` pinned-container wrapper within its unchanged
thirty-minute job budget. Generic major-version host jobs do not substitute for
these exact runtime placements or their required observed OS-image identities.

Each placement requests the original controller JSON through
`CHECKTRAIL_NATIVE_PROVENANCE_RUNTIME_RECEIPT` at a runner-temporary file. The
pinned artifact uploader retains that exact file only after its producing step
succeeds, with a distinct slot/attempt artifact name and a missing-file failure.
The ARM wrapper transports the container's receipt to the same host output path.
This wiring prepares observations; it does not assert that a hosted run passed,
that all eight receipts were independently reconciled, or that Gate A is complete.

These controls and their CI wiring do not by themselves qualify the final eight
runtime slots, prove native-positive verification for all four families, close the
selected upstream ancestry/notices, or freeze Gate A. The profile remains declared pending until
those required observations and dispositions are reconciled.

The internal `verify-native-provenance-runtime.mjs` controller prepares finite
current-source and fresh offline installation receipts. Pass one exact runtime
ID from `gate-a-profiles.v1.json`, or explicitly pass `--development` for an
unqualified local run. Runtime admission compares the exact Node patch, platform,
architecture and observed image fields before any cohort; major-only CI jobs
cannot substitute for the selected eight-slot matrix.

Both modes require the same nine callbacks. The source installed callback retains
its fresh nine-case envelope in a protected temporary namespace. The fresh harness
runs outside the installed package, resolves its engine and default coordinator
from that installation, and does not install recursively. The existing ninth
callback's installed broken/fixed/near-miss controls remain real additional
observations. Copied first-party guard counterfactuals remain synthetic tests;
these receipts do not trace every loaded module or reproduce the source build.

Receipts bind the source Git identity and cleanliness, complete declared harness
bytes, current compiled engine before/after, selected runtime and Node executable,
actual tarball SHA-256 and generated production-lock SHA-256. Unselected development
receipts explicitly qualify no slot. Source/fresh receipts must be independently
reconciled across all eight selected runtimes before native acceptance; this
controller's implementation does not promote the pending profile, freeze the
inventory, establish complete upstream license/build closure or close Gate A.

The source controller now observes the repository's literal TypeScript build in a
fresh temporary output directory before acceptance. It binds all current `src`
and `test` inputs, configuration, package/lock files and the selected TypeScript
entry files before/after that invocation. Both complete emitted engine and test
trees must match the existing artifacts to be tested; stale or orphaned artifacts
refuse admission rather than being relabelled current. Rebuild the checkout with
its ordinary build command before retrying a stale-artifact refusal.

The resulting finite build witness travels through the protected source-parent
receipt namespace. The package controller and installed harness inherit and
reconcile that witness, exact compiled callbacks and engine without rebuilding or
loading checkout modules. Git-only source metadata still declares
`compiledFromSourceVerified:false`; the separate observed build witness is
required before a selected slot can qualify. This witnesses one first-party
TypeScript emit, not hermetic compiler/dependency or upstream producer closure.
