# Whole lifecycle acceptance

The selected `lifecycle-platforms` profile has original synthetic controls for the
shared library, CLI and official MCP SDK. The source fixture has two enabled rows
and one disabled row, and starts two ordinary workers before its test can finish.
The broken implementation counts the disabled row; the repair keeps the same test
and removes that defect. Both outcomes must release every reached process before
returning. A literal filename containing spaces and a semicolon remains valid.

Preflight controls refuse execution without operator trust and reject absent or
changed declared loader bytes without importing a loader or reaching a project
body. A successful test followed by a source change remains incomplete. Empty
unparseable evidence keeps its count unknown, while an explicitly skipped case
retains its skipped count; neither becomes passing validation. The CLI and MCP
controls exercise startup execution/detail grants and retain raw diagnostics only
through the detailed surface. An unrelated synthetic environment value must not
reach the project.

The interruption fixture starts ordinary and detached workers, waits for their
actual bodies, and observes cancellation, deadlines, output exhaustion and loss
of the controlling process. Controlled interruption must remove its actual
engine-owned temporary directory. An unrelated sibling remains alive. POSIX
observations use native start identities and process groups; Windows requires the
native Job Object receipt and physical process disappearance. Bootstrap refusal
and other native platform obligations remain required in the preserved platform
foundation profiles. The lifecycle collector now runs the selected native
foundation after its whole-profile controls: POSIX cleanup and ownership on
Linux/macOS, or Windows process ownership and physical output on Windows.
Completion requires both sets. Exact required case accounting, unchanged engine
bytes and unchanged harness inputs cover the combined run. The fresh package
repeats the same platform selection from the external harness. A passing whole
profile cannot excuse an absent foundation callback. Laravel cache isolation retains its nine separate native controls. The source
and fresh-package collectors now require exact named-case accounting and bind the
same declared harness and compiled engine, observed Node/PHP executable identities,
SQLite availability, and selected framework versions and bytes before and after
execution. The installed harness is outside the installed package. The existing
pinned native Laravel job requires both envelopes and the binding refusal
controls. These selected observations do not establish complete PHP dependencies,
loaded modules, operating-system bytes or publisher/license closure. Wider final
runtime bindings remain required.

Run `node scripts/verify-lifecycle-platforms.mjs` after compilation. Its exact
callback selection comes from the finite inventory. The installed callback runs
`verify-lifecycle-platforms-package.mjs`, which creates a locked offline production
installation with lifecycle scripts disabled and repeats the same controls from
an external harness. Engine artifact identity, the Node executable identity and the complete declared
harness inputs must remain unchanged. Source and installed receipts bind the same
harness digest. Unknown or mismatched runtime slots are refused before any test
body. A development invocation without a slot remains explicitly unqualified.
The existing seven hosted engine jobs and pinned native ARM64 job require these
source/fresh controls; the controller reuses their observed runtime selection
policy. Observed image metadata does not authenticate the image or publisher. The source and fresh package require acceptance on every selected
engine runtime before profile promotion.

The [dated matrix](measurements/runtime-source-install-matrix-2026-10-26.json)
records the complete source/fresh cohort and selected platform foundation for
every selected runtime at its pinned candidate. The implementation is declared
with these historical receipts; later engine, dependency or harness changes still
require current-candidate acceptance. Inventory freeze and Gate A remain open. No
model inference, held-out case inspection or field evaluation follows from this
harness. POSIX ownership has the bounded observation limits documented in
[POSIX-CLEANUP.md](POSIX-CLEANUP.md), including visibility after a detached child
escapes and the absence of a durable-report guarantee after abrupt caller loss.

The separate fresh Windows foundation collector now requires both the native
Windows process profile and the physical-output profile. Portable development
invocations run the argument/environment contract and physical-output controls;
they do not qualify Windows. The receipt binds source and installed engine bytes,
all declared controller/test inputs, and exact required case accounting before
and after acceptance. Native Windows qualification remains required.

Source controllers retain the fresh-install receipt produced by their installed
acceptance callback in a new private temporary namespace. Before returning source
evidence they require the same selected runtime, compiled engine, harness inputs
and exact complete case ledger. Missing, malformed or mismatched receipts fail
admission. The namespace is removed after collection. Installed controllers do
not recursively create another installation. This is internal acceptance
bookkeeping and grants no operator trust or project execution permission.

The hosted and ARM64 wrappers consume that validated nested receipt rather than
running the complete installed cohort a second time. Both actual source and
fresh offline execution remain required in the same job; no previous job's
receipt substitutes for execution. The Windows job has a 45-minute aggregate
allowance for its combined Tasks, review and lifecycle work. Individual callback,
cleanup and project execution deadlines are unchanged.
