# Selected C++ source context

Opt-in context version 21 uses the existing pinned C++ WASM grammar over captured strings. The shared engine, CLI and MCP retain whole touched functions and decisions, declaration initializers and parameter defaults, exact ASCII names, literal constant reads and bounded lexical caller candidates under explicit disjoint source roots. `.h` chooses C++ only for this profile. Capture invokes no compiler, preprocessor, initializer, build file or project configuration. Versions 1–20 retain their contracts.

The bounded subset covers plain free functions with primitive return types, file scope and flat named namespaces, namespace reopening, literal `const`/`constexpr` declarations, ordinary nested blocks, parameter defaults, simple file-scope namespace aliases and selected quoted relative `.h`/`.hpp`/`.hh`/`.hxx` headers. A local declaration enters scope after its declarator, before its initializer. Parameters and local values mask unqualified function candidates. Default expressions look in the enclosing file/namespace, with earlier parameters masking names; the current parameter does not mask its own default. The owning function and initializer declaration retain their source addresses. A function becomes a candidate after its complete declarator.

An explicit `::name` uses file scope. A namespace or namespace alias qualifier selects that namespace; a local value with the same spelling does not hide the qualifier. An included header contributes declarations and aliases only after the captured include site. Arbitrary neighboring C++ source files contribute no declarations. Repeated definitions, overloads and duplicate include/alias candidates remain ambiguous. Alias traversal is bounded to eight steps; include traversal stops at eight levels, 256 visits or 4096 contributed declarations and aliases.

A selected header is a source candidate, not proof of native include search or a compiler translation unit. Unselected headers can define macros, so they keep dispatch unknown. Preprocessor directives, line splicing, guards, system/macro includes, prototypes and linkage, classes, templates, nested/anonymous/inline namespaces, using declarations, complex types, attributes, lambdas, ADL, build selection and ABI remain explicit unknowns. Function-pointer factories retain distinct inner and outer call ranges; the outer indirect call and construction calls stay unresolved. Caller depth is eight, with full impact fallback and unchanged validation planning.

Original synthetic Linux ARM acceptance uses Node 22.23.2 and the fixed parser. Supplementary G++ 14.2.0 witnesses compile broken, repaired and valid boundary examples, distinguish parameter-default and namespace-qualification rules, and exercise a fork/reap cleanup worker. These witnesses do not promote native name resolution, general C++ compilation or runtime reachability. Offline installed acceptance uses the original callbacks against production package bytes. Unavailable optional host checks remain skips. Full artifact/notice closure and final release acceptance remain separate Gate A obligations.

Declaration and function display names are bounded to 256 UTF-16 code units. Valid longer names retain complete source ranges with null display names and explicit unknown binding metadata; they cannot abort context capture. Original boundary fixtures and compiling guard controls exercise the supported and first unsupported lengths in source and fresh installed acceptance.
