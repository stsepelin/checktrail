# Selected HCL source context

Opt-in context version 22 uses the existing pinned HCL WASM grammar over captured strings. The shared engine, CLI and MCP retain selected declaration and traversal addresses, complete conditional decisions and bounded reverse declaration dependencies under explicit disjoint source roots. Capture does not evaluate expressions, load modules, initialize providers or run project configuration. Versions 1–21 retain their contracts.

The bounded source subset identifies top-level Terraform-shaped `variable`, `locals`, `output` and `module` blocks in `.tf` and `.hcl` files. A variable's default, an output's value and a local attribute's expression retain initializer spans. Exact case-sensitive `var.name` and `local.name` traversals resolve only among captured declarations in the same directory and revision; locals may refer forward. Duplicate definitions remain ambiguous. Type constraints are source declarations rather than value reads. Comments and inert literal strings add no references. HCL is an application-configured language: these shapes do not establish the application's evaluation semantics.

A module candidate requires a captured literal relative source, no `count`, `for_each`, `providers` or `version` selector, and a target directory inside the owning selected root. Its candidate list records every captured `.tf` file in that directory. Exact `module.name.output` traversals resolve selected output declarations across those files. A representative target file in the common module table is supplemented by the complete bounded candidate list. Remote, absolute, escaping, missing, dynamic and unselected sources remain unknown; source selection is not native module loading. Module input values are not propagated.

References retain source ranges, declaration owners, selected or unresolved resolution states and revision-bound identifiers. An output reference belongs to the output block so reverse dependencies can cross selected module output boundaries. Reverse traversal stops at eight levels or 4096 edges, reports cycles and retains full impact fallback with unchanged validation planning. No functions or runtime callers are synthesized for configuration data. For expressions, indexed/splat traversals, template directives and application-specific blocks stay unsupported. `.tfvars` input overrides and non-HCL source remain explicit unknowns. Intake reconciles roots, references, counts, module file candidates, omissions, grammar identity and reverse dependencies.

Original synthetic Linux ARM acceptance uses Node 22.23.2 and the fixed parser. Supplementary Terraform 1.16.5 witnesses distinguish broken, repaired and valid identifier-boundary configurations without external providers. Explicit trusted execution of a built-in local resource exercises cancellation, timeout, output limits and descendant cleanup. These witnesses do not promote native evaluation, loading, input values or runtime reachability in captured context. Offline installed acceptance repeats the original callbacks against production package bytes. Unavailable optional host checks remain skips. Full artifact/notice closure and final release acceptance remain separate Gate A obligations.

Declaration and function display names are bounded to 256 UTF-16 code units. Valid longer names retain complete source ranges with null display names and explicit unknown binding metadata; they cannot abort context capture. The bound does not truncate HCL module source strings. Original boundary fixtures and compiling guard controls exercise the supported and first unsupported lengths in source and fresh installed acceptance.
