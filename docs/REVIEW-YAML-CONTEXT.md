# Selected YAML source context

Opt-in context version 23 uses the existing pinned YAML WASM grammar over captured strings. The shared engine, CLI and MCP retain anchor declarations, value initializer spans, alias source addresses, complete mapping decisions and bounded reverse declaration dependencies under explicit disjoint source roots. Capture runs no deserializer, tag constructor, template, include loader or consuming application. Versions 1–22 retain their contracts.

Exact ASCII anchor and alias names within the 256-character declaration bound resolve to the most recent preceding captured anchor in the same file, document and revision. Reusing a name is allowed; the preceding occurrence determines each source candidate. Forward aliases and aliases in another document or file remain unresolved. Anchored scalar, block and flow values retain the complete initializer rather than the anchor token alone. Aliases inside an anchored value belong to that declaration so reverse source dependencies can follow an alias chain. Ordinary consumers belong to their mapping declaration. Comments, quoted strings and block scalar content create no alias references.

Tags, merge-key consumers, longer, non-ASCII or complex anchor names and recursive aliases remain explicit unknowns. Capture does not expand aliases, materialize scalars or infer environment/configuration consumers. No functions or runtime callers are synthesized. Native serialization, scalar resolution, merge semantics and consumer behavior remain unverified. Reverse declaration traversal stops at eight levels or 4096 edges, preserving full impact fallback and unchanged validation planning. Metadata retains every alias, including unresolved candidates. Intake reconciles roots, declaration addresses, ordering/document candidates, reference counts, grammar identity, omissions and dependency closure.

Original synthetic Linux ARM acceptance uses Node 22.23.2 and the fixed parser, with supplementary YAML 2.9.1 deserialization witnesses. Broken, repaired and valid identifier-boundary data produce different outcomes in an explicit synthetic consumer. Trusted parser-worker execution exercises cancellation, timeout, output limits and descendant cleanup only after readiness proves both processes are alive. These witnesses do not promote consuming-application semantics or runtime impact in source context. Offline installed acceptance repeats the original callbacks against production package bytes. Optional unavailable host checks remain skips. Full artifact/notice closure and final release acceptance remain separate Gate A obligations.
