# Original GCC main bootstrap continuation

The fixed main05 carrier prepares one next original Debian GCC 12 build phase.
It is separate from ordinary PR CI. It requires a separately reviewed operator
execution action; import, discovery and planning do not run producer code.
It has not yet qualified a hosted main bootstrap or whole GCC producer closure.

The only selected native command is:

```text
dpkg-buildpackage -b -us -uc --jobs=4 --rules-file=/controller/gcc-staged-rules2.sh --rules-target=stamps/05-build-stamp
```

The original outer Debian transition and rules2 forwarding remain in control.
The original selected language, multilib, bootstrap, JIT, offload, HPPA64,
check, documentation and package graph is retained. Later graph phases remain
pending. Separate phase commands do not reproduce an uninterrupted
`dpkg-buildpackage` invocation.

Before SDK preparation, a fixed source-hash-pinned operator history must retain
the complete reviewed attempt ledger and original configuration. The initial
history contains the authenticated configure row; a later attempt requires new
reviewed full-history source pins that preserve every failed charge. A phase0
replay cannot reset an already-frozen failed history. The source cohort selects
native only, and a platform rerun requires a new independently reviewed action.
The shared data contract also derives the finite later original commands,
repeated required stamps, report obligations and package output families; this
does not activate those phases or qualify their capacities.

Before the command, the carrier independently restores the pinned configure
cache, authenticates its complete original source/HOME/APT/temporary/report
state and graph, and reconstructs the original SDK. The SDK contract requires
exact compiler, header, library, font, script, configuration and package
identities. Its finite generated-state policy separately regenerates and
validates the known font, linker and TeX outputs; it does not assert equality
with unretained historical cache bodies or an identical full operating root.
A stopped, verified materializer is committed only to a new owned local image.
No image registry publication occurs.

The source state is physically relocated without another working-source copy.
Native admission then reobserves actual CPU, memory, disk, shared cache and
source-job clock. The 32 GiB state and independent replay, 4 GiB archive,
8 MiB envelope and 128 MiB shared-cache margin are finite upper limits. They
are not measured compression or stock-host fit. Compiler state, complete GCC
stdout and reports cannot be dropped to meet a limit. Cache space is unreserved; no
unrelated cache, toolchain, quota or runner setting is removed or changed.

The six-hour source-job clock includes preparation, attach startup, checks,
cleanup, retention, transfer and finalization. The admission reserves 7,200
seconds for explicitly bounded finalization stages; it can reduce or refuse
the body window. The body window does not promise that much time for the
original command alone. The genuine dpkg duration and exit or signal are
retained separately from the observer, wrapper and container outcomes.

Owned container/image cleanup also covers successful creation followed by
failed inspection or a lost returned value. Recovery requires retained intent,
physical ownership and exact identity; a rebound tag, unproven resource or
ambiguous result cannot authorize broad cleanup. Actual SDK/native elapsed
time remains charged when later checks or retention fail. A genuine zero with
an unconfirmed family creates a charged `terminal-incomplete` row with no
checkpoint. Such a row blocks every continuation; there is no caller Boolean
that clears it. Independently observed owned cleanup can close an observation
before failure reconciliation, without changing the original terminal result.

A successful local archive plus independent physical replay produces only a
provisional ledger. `localCheckpointCapturedAndPhysicallyRestored` describes
that local scope. Service credit additionally requires one exact fresh cache
key, removal of the original local transport directory from the restore path,
independent service restore, full physical source replay and exact cache API
identity/size readback. A real original zero followed by capture or service
failure remains a charged retention failure with no promoted checkpoint.
Partial, stale, wrong-container, wrapper-only or missing observations cannot
supply an original terminal result.
