# Independent evaluation setup acceptance

The `independent-evaluation-protocol` profile exercises a connected operator
pipeline with original synthetic declarations, source, captures, judgments,
common-defect mappings and usage observations. It validates protocol handling
and receipt reconciliation. Actual review-host independence, label authority,
configuration authenticity, billing and review quality require later evidence.

The library exposes bounded protocol/capture/metering inspection, private
physical artifact storage, capture sealing, anonymous judgment packets,
independent mapping and paired scoring. Operator scripts accept bounded input
through stdin. Private identities and configuration bytes remain in operator
storage; public protocol declarations retain opaque identities and digests.
The comparison baseline is plain Codex/Claude review with repository instructions.

The whole synthetic profile covers broken, repaired and valid adjacent programs,
prerequisite refusal, source freshness, empty evidence, privacy and lifecycle
controls. Source and fresh offline installation each require every callback to
pass without skips. The installed harness and external MCP test client remain
outside the production installation. Compiled engine, harness, runtime, package
and lock bindings accompany the observation. Missing, duplicated, skipped,
changed or foreign receipts fail admission.

Runtime admission also pins the acceptance test file before and after execution
and reconciles each required case with its passed terminal event, file identity
and sequence. Matching callback names and totals alone cannot admit a foreign
file ledger. Source and installed receipts use the same validator. The hosted
core lanes run the evaluation cohort once per selected slot; the separate
consumer-only Windows lane does not duplicate it.

Run the synthetic source profile after building:

```sh
node scripts/verify-required-native-tests.mjs independent-evaluation-protocol
```

`verify-evaluation-runtime.mjs SLOT` binds source and installed execution to a
selected runtime. Hosted Tasks jobs and the pinned native ARM64 controller are
wired to collect those receipts. Windows additionally requires literal private
ACL batch controls; the production batch inspector reads permissions without
repairing them. Newly wired hosted runs remain unverified until observed.
