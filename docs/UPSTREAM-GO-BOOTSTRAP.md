# Original Go C-root source observation

This is explicit development/CI tooling, separate from product CLI/MCP discovery.
The frozen catalog requires the maintained C-source bootstrap and the seven named
Go source stages, including both 1.17 branches and both final branches. Its exact
archives, original commands, environments, predecessors and resource limits are
in `scripts/producer-qualification/go-bootstrap.v1.json`. Native acceptance is
pending. Source code, pure controls and a hosted wrapper do not qualify a build.

The default child input is the sealed SDK produced by its successful current
predecessor. Full physical inventories bind regular bytes, modes, ownership and
contained link targets before and after child execution. Historical regular-file
manifest hashes are comparison evidence. A mismatch prevents an exact historical
private-input replay claim; it does not supply a prebuilt replacement or veto a
separately proven current-source ancestry. The current controller does not import
SDKs or phase results supplied by a model/operator as alternate parents.

The Go-specific independent retention program uses the existing observer protocol
and lifecycle, with an explicit pinned source-to-entry filename binding. It checks
the regular-leaf bound across all retained roots and refuses links in retained work.
An unexpected link therefore leaves this finite observation incomplete even when
the SDK inventory can describe it; general linked SDK output qualification is not
claimed. No links are followed or silently excluded from the SDK seal.

Each original command keeps its CPU, RAM, PID and per-call timeout policy. The
maintained bootstrap's version call is 60 seconds. Later source stages preserve
CGO_ENABLED=0 and their original environment; release `-distpack` builds with CGO
unset remain a separate obligation. The archive's original VERSION text is retained
separately from the built executable's version assertion, including timestamp
metadata in newer source archives.

Data acquisition fetches only the eight pinned official source archives. Native
execution requires an observed Linux x64 host/kernel, the exact immutable image,
a committed source/caller startup frame and a new private output namespace.
Selected controller/helper file bytes and modes must match the committed tree;
this does not run repository status hooks/clean filters or assess whole-checkout
cleanliness. Compiler/interpreter/linker bytes and the current predecessor seal are observed
before and after original commands. Filesystem retention is independently sampled
through the existing read-only observer. Its counters are reconciled from the
physical log. This is an observation, not a native filesystem quota or hardware
attestation.

The new observation caps are 16 GiB owned work, 512 MiB per regular retained leaf,
64 MiB per command output and 512 MiB aggregate output. The external window ends
350 minutes after startup, including data preparation. The hosted job has a
360-minute ceiling for final owned cleanup/export. These caps can interrupt an
original command and leave remaining work not run. They do not replace its
original timeout or promise support for the sum of all original maximum budgets.
Failed/canceled/raw output is retained before original semantic assertions.
Docker-client stdout/stderr are combined in the parent's observed event order;
native cross-stream interleaving is not inferred.

The dedicated workflow uploads only caller-owned receipts, raw observation logs
and SDK metadata seals. It does not recursively upload root-owned SDK/cache trees.
The one-job implementation mounts only the fresh current stage as writable work;
its sealed predecessor is a sibling mounted read-only. Controls, source archives,
receipts and other stage roots have no writable builder mount. Physical root and
ancestor identities reject linked/replaced roots and writable SDK ancestors or
descendants. Before starting an original command, the controller creates its owned
container and retains the actual daemon configuration. Both requested and effective
bind graphs, exact command/environment/image and resource settings must match.
It then starts attached, retaining the client terminal and separately inspecting
the actual exited native state before cleanup. Setup consumes the original command
budget. Missing inspection or cleanup leaves the observation incomplete. These
checks observe the local daemon; they do not attest the host, kernel or hardware.
No cross-job resume or historical artifact fallback is implemented.

All broader C/compiler/SDK/base-image ancestry, inline/copied original notices,
crypto/test payload generators, Darwin/ARM64/signing/publisher obligations and
Gate A remain open. No model inference, review comparison or field trial is run.
